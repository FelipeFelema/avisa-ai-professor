## Governance Gate and Review

- Before the amendment, Technical & Product Constraints required privileged registration to continue through invite codes. This conflicted with Spec 009's requirements that public invites create PROFESSOR only and ADMIN provisioning remain manual and outside the app.
- Amendment reviewed on 2026-10-04: public registration now creates PARENT by default or PROFESSOR through a valid professor invite; it cannot create ADMIN. ADMIN provisioning is operational/manual outside the application.
- Concrete rationale: restricting the public registration surface prevents a public invitation or manipulated request from granting administrative authority, while retaining the supported ADMIN role for existing accounts and operational provisioning.
- Version decision: `2.0.0` (MAJOR), because the existing public ADMIN-by-invite behavior is redefined incompatibly. Ratification date remains `2026-08-22`; Last Amended is `2026-10-04`.
- Template impact review: `.specify/templates/plan-template.md` contains a generic Constitution Check placeholder and needs no policy-specific change. `.specify/templates/constitution-template.md` contains generic principle/governance placeholders and needs no policy-specific change. Other templates contain no policy copy requiring synchronization.
- Compliance review: the amendment preserves the global ADMIN role, requires backend authorization tests, and does not authorize a production ADMIN endpoint. Phase 2's test-only helper must assert safe test-database configuration before writes and must authenticate through the HTTP login flow.
- Review outcome: amendment is consistent with the spec's role boundary and existing secure-contract principles. At that review stage, implementation beyond Phases 1 and 2 was not authorized.
